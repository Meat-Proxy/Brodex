# Brodex

<img src="extension/images/brodex-128.png" width="64" height="64" alt="Brodex">

Экспериментальное управление Chrome через локальный MCP. Windows, Chrome и Node.js 20+. Приоритеты: функциональность → точность → скорость. **2.53.1 — экспериментальная сборка с исправлениями установки для Windows PowerShell 5.1**, не официальный продукт OpenAI или Google.

## Возможности

DOM-каталог и AX, чтение больших списков порциями, DOM без мыши / DOMмышь / координатные действия, подготовка и контроль изменений, группы задач, снимки и операции с файлами. Поддержанные iframe и открытый Shadow DOM проходят проверку полноты. Отправка действия не выдаётся за подтверждение результата.

## Установка

**Через Codex:** попроси «Установи Brodex из https://github.com/Meat-Proxy/Brodex по INSTALL-CODEX.md». [Инструкция для агента](INSTALL-CODEX.md) использует `setup.ps1 -Action Install`: мост, навык и MCP устанавливает Codex, расширение пользователь загружает вручную в Chrome и сообщает ID. Затем Codex выполняет Register и проверяет подключение. Используй [архив версии v2.53.1](https://github.com/Meat-Proxy/Brodex/archive/refs/tags/v2.53.1.zip): он содержит эту инструкцию и установщик; прежний v2.53.0 их не содержит.

### Ручной вариант

1. Установи Node.js 20+ и Chrome. Скачай ZIP исходников и распакуй в отдельную папку.
2. Из этой папки выполни в PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Action Stage
```

Комплект размещается в `%LOCALAPPDATA%\Brodex\App`, native launcher компилируется средствами установленного .NET Framework. Для другого пути указывай одинаковый `-InstallDir` во всех командах. Администратор не требуется. Скрипт не скачивает зависимости.

3. В `chrome://extensions` включи режим разработчика, выбери «Загрузить распакованное расширение» и папку `%LOCALAPPDATA%\Brodex\App\extension`.
4. Открой «Подробнее» у Brodex и включи «Разрешить использование в режиме инкогнито». Скопируй выданный Chrome ID:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Action Register -ExtensionId ВСТАВЬ_ID_ИЗ_CHROME
```

5. Перезагрузи расширение. Установщик напечатает команду `codex mcp add brodex -- ...`. Выполни её или добавь MCP через настройки Codex: команда — абсолютный путь к node.exe, аргумент — путь к `Brodex\App\bridge\server.cjs`.
6. Скопируй `%LOCALAPPDATA%\Brodex\App\skill\brodex` в `%CODEX_HOME%\skills` либо `%USERPROFILE%\.codex\skills`. Существующий навык предварительно сохрани отдельно.
7. Перезапусти подключение MCP/чат при необходимости и попроси агента использовать Brodex и проверить `status`.

Если уже зарегистрирован другой Brodex, Register откажется переключать его молча. `-ReplaceRegistration` означает намеренное переключение; прежний путь сохраняется в `registration-before.json`. Регистрация штатного расширения OpenAI не меняется.

## Обновление и откат

Заверши работу агента, останови MCP и закрой Chrome. Из новой распакованной версии выполни Stage с прежним InstallDir. Конфигурация моста сохраняется, предыдущий код остаётся рядом в `App.previous`. Затем запусти Chrome, перезагрузи расширение, обнови копию навыка и перезапусти MCP.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Action Rollback
```

Rollback возвращает предыдущий код по прежнему пути; заменяемая версия сохраняется отдельно. Данные задач не удаляются. Перед следующим обновлением перемести `App.previous` в свой архив: установщик не стирает его автоматически. Копия навыка в Codex восстанавливается отдельно из сохранённой тобой копии.

## Приватность и ограничения

### Удаление

Для установки с новым учётом компонентов: останови MCP, удали расширение вручную в Chrome и из распакованного комплекта выполни `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Action Uninstall`. Передай прежние `-InstallDir` и `-CodexHome`, если они нестандартные. Удаляются проверенные файлы программы, принадлежащий установщику навык, MCP и регистрация моста. Изменённые или чужие компоненты вызывают отказ. Данные задач и резервные копии **сохраняются**; полного режима очистки пока нет. Старые ручные установки автоматически не присваиваются. Ранее заменённая регистрация другого моста автоматически не восстанавливается.

### Хранение

Расширению нужны доступ к страницам и Chrome debugger. Подключай только доверенные MCP-клиенты. Переданное клиенту/агенту содержимое уже вне управления Brodex.

Token/pipe и привязка ID создаются локально и не должны публиковаться. Обычные служебные данные: `%LOCALAPPDATA%\Brodex\Data`; приватные журналы: память MCP. DOM-эталоны, снимки и исключения не записываются в служебные файлы. Старое непустое хранилище без маркера требует миграции и не перезаписывается.

Известные ограничения: привязка группы после перезапуска Chrome может требовать восстановления; canvas, закрытые Shadow DOM и некоторые перекрытия не поддерживаются как обычные DOM-цели. Непрерывная проверка всех CSS/пиксельных изменений не гарантируется. См. [изменения интерфейса](docs/migration.md) и [границы тестирования](docs/validation.md).

## Разработка

Runtime использует встроенные модули Node.js. Для тестов отдельно установи Playwright: `npm install --no-save playwright`, затем `node run-tests.cjs`. Можно задать BRODEX_PLAYWRIGHT_MODULE и BRODEX_CHROME_PATH. По умолчанию тесты ищут Chrome в Program Files. Артефакты `.test-output` исключены из Git и релиза.
