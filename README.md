# Brodex

<img src="extension/images/brodex-128.png" width="64" height="64" alt="Brodex">

Экспериментальное управление Chrome через локальный MCP. Windows, Chrome и Node.js 20+. Приоритеты: функциональность → точность → скорость. Экспериментальный проект, не официальный продукт OpenAI или Google.

## Возможности

DOM-каталог и AX, чтение больших списков порциями, DOM без мыши / DOMмышь / координатные действия, подготовка и контроль изменений, группы задач, снимки и операции с файлами. Поддержанные iframe и открытый Shadow DOM проходят проверку полноты. Отправка действия не выдаётся за подтверждение результата.

## Установка

**Через Codex:** скопируй в новый чат:

> Установи Brodex из https://github.com/Meat-Proxy/Brodex по INSTALL-CODEX.md. Используй последний опубликованный выпуск, включая предварительные выпуски.

[Инструкция для агента](INSTALL-CODEX.md): Codex устанавливает мост, навык и MCP. Ты вручную загружаешь расширение в Chrome и сообщаешь «установлено». ID передавать не нужно.

### Ручной вариант

1. Нужны Windows, Chrome, Node.js 20+ и доступная команда Codex CLI. Открой [Releases](https://github.com/Meat-Proxy/Brodex/releases), выбери самый новый опубликованный выпуск, включая **Pre-release**, скачай **Source code (zip)** и распакуй. Инструкция и установщик должны быть из одного выпуска. Ветка main предназначена для разработки.
2. Из распакованной папки выполни в PowerShell:

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Action Install
~~~

Установщик размещает комплект в %LOCALAPPDATA%\Brodex\App, регистрирует мост, устанавливает навык и MCP в Codex. Native launcher компилируется средствами установленного .NET Framework. Администратор не требуется; зависимости скрипт не скачивает. Пути определяются для текущего пользователя. Для других путей передавай одинаковые параметры -InstallDir и -CodexHome во всех командах.

3. Самостоятельно открой в Chrome **chrome://extensions**, включи «Режим разработчика», выбери «Загрузить распакованное расширение» и папку **%LOCALAPPDATA%\Brodex\App\extension**.
4. В «Подробнее» у Brodex включи **«Разрешить использование в режиме инкогнито»**.
5. Сообщи агенту «установлено». Переподключи MCP или начни новый чат, если клиент не подхватил настройку. Агент проверит живую связь через Brodex status.

Успешная установка файлов ещё не подтверждает соединение с Chrome. Если уже зарегистрирован другой Brodex, установщик откажется переключать его молча. Параметр -ReplaceRegistration означает намеренное переключение; прежний путь сохраняется в registration-before.json. Регистрация штатного расширения OpenAI не меняется.

## Обновление и откат

При переходе с 2.53.1 и более ранних сборок ID расширения меняется. Выполни однократную переустановку компонентов после их резервного копирования и остановки, затем заново загрузи папку расширения. Старое расширение оставь выключенным или удали вручную. Установщик отказывает в обычном Stage при несовпадающей привязке, не меняя её молча. Данные задач при штатном удалении сохраняются. Подробнее: [идентичность расширения](docs/extension-identity.md).

Заверши работу агента, останови MCP и закрой Chrome. Из новой распакованной версии выполни Stage с прежним InstallDir. Конфигурация моста сохраняется, предыдущий код остаётся рядом в `App.previous`. Затем выполни `setup.ps1 -Action Connect` с теми же путями для обновления управляемого навыка, запусти Chrome, перезагрузи расширение и перезапусти MCP. `Install` возобновляет настройку, но не обновляет уже установленный код.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Action Rollback
```

Rollback возвращает предыдущий код по прежнему пути; заменяемая версия сохраняется отдельно. Данные задач не удаляются. Перед следующим обновлением перемести `App.previous` в свой архив: установщик не стирает его автоматически. После Rollback выполни `setup.ps1 -Action Connect` с теми же путями для согласования навыка.

## Удаление

Для установки с новым учётом компонентов: останови MCP, удали расширение вручную в Chrome и из распакованного комплекта выполни `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Action Uninstall`. Передай прежние `-InstallDir` и `-CodexHome`, если они нестандартные. Удаляются проверенные файлы программы, принадлежащий установщику навык, MCP и регистрация моста. Изменённые или чужие компоненты вызывают отказ. Данные задач и резервные копии **сохраняются**; полного режима очистки пока нет. Старые ручные установки автоматически не присваиваются. Ранее заменённая регистрация другого моста автоматически не восстанавливается.

## Приватность и ограничения

Расширению нужны доступ к страницам и Chrome debugger. Подключай только доверенные MCP-клиенты. Переданное клиенту/агенту содержимое уже вне управления Brodex.

Token/pipe создаются локально и не должны публиковаться. ID расширения и его публичный ключ опубликованы и не являются секретами. Обычные служебные данные: `%LOCALAPPDATA%\Brodex\Data`; приватные журналы: память MCP. DOM-эталоны, снимки и исключения не записываются в служебные файлы. Старое непустое хранилище без маркера требует миграции и не перезаписывается.

Известные ограничения: привязка группы после перезапуска Chrome может требовать восстановления; canvas, закрытые Shadow DOM и некоторые перекрытия не поддерживаются как обычные DOM-цели. Непрерывная проверка всех CSS/пиксельных изменений не гарантируется. См. [изменения интерфейса](docs/migration.md) и [границы тестирования](docs/validation.md).

## Разработка

Runtime использует встроенные модули Node.js. Для тестов отдельно установи Playwright: `npm install --no-save playwright`, затем `node run-tests.cjs`. Можно задать BRODEX_PLAYWRIGHT_MODULE и BRODEX_CHROME_PATH. По умолчанию тесты ищут Chrome в Program Files. Артефакты `.test-output` исключены из Git и релиза.

Порядок изменения версии и публикации: [выпуски](docs/releasing.md). Номера версий хранятся в основных файлах сборки и тегах; общие инструкции не привязаны к текущему номеру.
