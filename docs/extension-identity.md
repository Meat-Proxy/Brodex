# Постоянная идентичность расширения

Публичная сборка: `obommdbooabdkphocbelglolmlelanhc`.
Зарезервированная идентичность разработки: `lbhaembbiidhigjahnpfnkjogaljgbca`.

В scripts/extension-identities.json сохранены два различных публичных RSA-ключа и соответствующие ID. В extension/manifest.json включён только публичный ключ основной сборки. Ключи генерировались однократно; закрытые ключи не сохранялись. Это идентичности распакованных расширений, а не комплект для подписания CRX или подтверждение владения записью Chrome Web Store. Перед публикацией в магазине идентичность необходимо отдельно согласовать с его ключом.

Механизм Chrome: https://developer.chrome.com/docs/extensions/reference/manifest/key . ID вычисляется из первых 128 бит SHA-256 DER-ключа с отображением шестнадцатеричных цифр в a–p. Установщик проверяет формат ключа, выводит ID из установленного манифеста и разрешает native messaging только этому origin. Не регенерировать ключи при сборке, установке, смене пути или пользователя. Публичный key не секрет и не доказательство подлинности кода.

Install выполняет Stage → Register → Connect, а пользователь затем вручную загружает расширение и разрешает инкогнито. Register без аргумента ExtensionId определяет ID автоматически; явный несовпадающий аргумент вызывает отказ. Повторная установка сохраняет существующий token/pipe. Несовпадающая старая привязка не перезаписывается.

Переход с версии без key меняет Chrome ID. Нужна однократная переустановка после остановки и резервного копирования: удалить старые компоненты через их установщик, установить новую сборку, вручную загрузить расширение заново. Старое расширение не включать. Отдельная запись расширения получает отдельное хранилище Chrome; перенос настроек Chrome между ID автоматически не выполняется. Служебные данные Brodex штатный Uninstall сохраняет.

Разработка: второй ключ пока только резерв идентичности. Он не включается обычным установщиком. Для одновременного использования публичной и экспериментальной сборок ещё нужно разделить native host, имя MCP, пути установки и хранения. Различные Chrome ID сами по себе этого не обеспечивают.

Проверки: детерминированность ID, соответствие публичного манифеста, разные ID каналов, отказ неверного ключа/ID; установка в Windows PowerShell 5.1 и PowerShell 7 с реальным изолированным Codex CLI и имитацией регистрации native host. Живая загрузка этой версии в Chrome и совпадение фактического runtime ID пока отдельно не подтверждены.
