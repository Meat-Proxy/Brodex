# Действия на странице

Для поддержанных отдельных операций основной путь — [action_v2](recovery.md#протокол-action_v2). Описания prepare_action, prepare_click и специальных повторов ниже относятся к совместимому прежнему API; их токены и быстрый повтор в action_v2 не применяются.

Читать для DOM, меню, полей, клавиш, ожиданий и анализа разметки. Для мыши и снимков — [визуальные действия](visual-actions.md).

## Наблюдение и выбор метода

После `browser_work begin` используй новое `read_page` по актуальному URL. Возвращаются текст и элементы выбранного документа и доступных вложенных деревьев, признаки состояния и покрытия; значения полей опущены. `ready_state:complete` не подтверждает завершения динамической загрузки. Не считать отсутствие элемента установленным при truncated/неполном покрытии.

`max_chars` 100–30000, `max_elements` 1–100. Продолжение — text_offset/element_offset из next_* ответа; между частями страница может измениться. Каждый новый снимок заменяет прежний. DOM element_id действует в своём свежем snapshot_id до 60 секунд. in_viewport не означает, что элемент не перекрыт; чтение не прокручивает страницу. Не пытайся использовать старые ID после навигации, begin или нового чтения.

| Нужно | Метод и проверка |
|---|---|
| Перейти в раздел | Наблюдаемая ссылка/меню/поиск; navigate goto/back/reload при подходящей задаче; проверить фактический адрес |
| Раскрыть меню, подсказку или карточку DOM-наведением | act hover по свежему element_id → read_page или wait_after → проверить появившееся содержимое; нажатие не требуется |
| Нажать обычную видимую кнопку | act click; если событие проигнорировано, сначала проверить фактический результат |
| Ввести текст | act fill после проверки доступности поля; затем проверить value_matches и эффект |
| Выбрать option | act select с точным value из options |
| Установить флажок | act set_checked с явным checked; установить смысл конкретного переключателя |
| Прокрутить страницу / показать элемент | act scroll без element_id / с element_id; новое наблюдение |
| Прокрутить отдельную панель | wheel_at по проверенной точке, а не scroll(element_id) |
| Физический клик нужен вместо DOM | Свежий обзор → prepare_click → просмотр → click_at; только если нет запрета безопасности |

DOM и физический ввод могут вызывать разные реакции сайта. Не называй отсутствие реакции дефектом Brodex без доказательств. Переход к мыши — осознанный выбор после проверки исхода, не обход отказа видимости/перекрытия. Не начинай с заведомо неподходящего метода только ради формальной последовательности.

DOM задаёт цель, а не обязательно способ доставки клика: `act click` для пользовательской поверхности может сам выполнить наведение и отправить события мыши (`input_method:dom_target_pointer`). Агенту не нужно повторять такой клик координатной командой. Подготовка не выполняет наведение или нажатие. В подготовленном DOM-клике после собственного наведения исполнителя допускается только смена непрозрачных цветов текста/фона именованной цели и её потомков при сохранении остальных проверяемых свойств. Эталон цели не заменяется; до наведения сравнение остаётся строгим. Это ограниченная политика оформления, а не доказательство причины изменения CSS или неизменности смысла, закодированного только цветом. Цель, смысл которой определяется цветом, требует отдельного наблюдения перед выбором действия.

Если наведение нужно для раскрытия интерфейса, используй самостоятельный `act hover`, затем новое чтение и выбор появившейся цели. Изменения структуры, состояния, геометрии или перекрытие во время клика не разрешают нажать автоматически. `PREPARATION_TARGET_CHANGED` может содержать категорию первой разницы (`identity`, `state`, `geometry`, `style`, `attachment`, `parent`, `hit_target`); неполный отчёт требует свежего наблюдения, а не исключения или перехода к координатам.

Отказ DOM-действия разбирай по [отдельному DOM-циклу](recovery.md#цикл-отказа-dom-действия). Он не требует обязательного обзорного PNG; для специального повтора используются сохранённое действие, свежее DOM-чтение и просмотр возвращённого DOM-контроля.

Поиск контролов выполняет браузер по фиксированному селектору отдельно в обнаруженных доступных документах и открытых Shadow DOM. Перед действием список получается заново: сохранённый список не подтверждает текущее состояние. Скрытый контрол не исключается только из-за невидимости, поскольку его значение или выбранность могут влиять на действие. Произвольные div/span не требуют классификации или сворачивания ради поиска контролов; правила конкретных сайтов не используются.

`controls_coverage` описывает этот поиск, отдельно от локального `context_coverage` цели и общего `coverage` вложенных деревьев. `matched_controls` — число учтённых контролов; при `count_is_lower_bound:true` оно неполное. `candidates_examined` считает обработанные совпадения селектора, а `visited_nodes:null` означает, что внутренний обход браузера не измеряется. Предел — 256 контролов; отдельные ограничения — 30000 обрабатываемых кандидатов и 100 мс на поиск. `reason` различает `control_limit`, `candidate_limit` и `time_limit`. Нативный запрос нельзя прервать посередине: время проверяется до и после него, превышение запрещает действие. `complete:true` относится только к обнаруженным корням и не отменяет ограничения общего `coverage`. `controls_limit` обозначает превышение числа контролов; `controls_scan_limit` — неполный поиск при исходном чтении или повторной проверке. Ни один из этих отказов не разрешает ввод или исключение непроверенного контекста.

## Встроенные документы и компоненты

`read_page` по умолчанию читает основной документ, доступные HTTP(S) iframe того же источника и открытые Shadow DOM. Их внутренние кнопки, поля, флажки и другие поддержанные элементы получают обычные `element_id`; `embedded_scope` отмечает вложенность. Это реальные цели действий, а не только разрешение работать рядом с контейнером. Используй тот же DOM-цикл, тайминги, бюджеты ответа и протокол восстановления.

Если нужный iframe не прочитан вместе с родителем, проверь `coverage` и список `frames`. Выбери наблюдаемый `frame_id` и выполни `read_page` с ним; `expected_url` остаётся актуальным URL вкладки верхнего уровня. Доступный iframe другого источника читается через разрешённую браузером инъекцию в конкретный документ. Идентификатор не угадывать. Новое чтение другого документа также заменяет прежнее наблюдение. Дальнейшие действия наследуют документ из `snapshot_id`; отдельный параметр для каждого клика не нужен. Для возврата к родителю читай `frame_id:0` либо опусти его.

Для отдельного iframe `screenshot(frame_id)` возвращает PNG его viewport, а точки и области задаются в пикселях именно этого кадра. Все родительские рамки должны полностью показывать этот viewport. При `FRAME_SCREENSHOT_CLIPPED` сначала покажи iframe прокруткой родителя и заново прочитай его. Координаты полного окна и внутреннего снимка не смешивать. `wait_for(frame_id)` проверяет выбранный документ; `wait_after` автоматически сохраняет документ действия.

Подготовка и исполнение проверяют внутреннюю цель, границы и перекрытие рамки, идентичность документа, геометрию и фокус. Замена документа даже с тем же URL, перемещение рамки, перекрытие или перенос фокуса не превращаются в исключение. При таком отказе заново наблюдай родителя и нужный документ. Допустимые изменения обычного внутреннего контекста обрабатываются общими `retry_preparation` / `prepare_retry`; отдельного цикла для iframe нет.

`coverage` не гарантирует чтение всех вложений: есть ограничения глубины, числа рамок и объёма обхода. Закрытые Shadow DOM, документы с неподдержанной схемой или отказом Chrome, трансформированные/CSS-масштабированные цепочки iframe остаются недоступными выбранному адаптеру. `iframes_not_read` — непрочитанное содержимое, а не пустой документ. Canvas/video не становятся DOM-элементами управления из-за попадания в рамку. Соседство поддержанного iframe/Shadow DOM само по себе не причина отказа; имеет значение полнота конкретного проверяемого контекста. Передача файлов имеет отдельные [границы загрузчика](upload-policy.md).

## Компактный контекст действия

Для DOM click/fill/select/set_checked/hover доступен необязательный `action_context`. Копируй kind и при необходимости name из того же свежего элемента read_page; name с секретом или лишними личными данными опускай. expected_effect описывает намерение агента, не подтверждённый эффект и не разрешение пользователя. Значения форм, сообщения, токены и заявления о полномочиях сюда не передавай. Проверка сопоставляет kind/name со снимком; контекст не заменяет цель задачи, авторизацию или проверки элемента. Не сочиняй каждый раз длинное объяснение вместо этих полей.

## Размер контекста ответа

У поддерживающих команд обычный ответ `compact`: до **3000 символов текста и 20 элементов всех типов** в порядке извлечения. Не передавай параметры ради повторения этих значений. При нехватке контекста агент может сам задать `response_budget: {max_chars, max_elements}`: 100–30000 символов, 1–100 элементов; пропущенная часть бюджета сохраняет свой default. Например, 6000/40 для более длинного результата. `response_mode:full` возвращает исходное наблюдение и не сочетается с response_budget.

Бюджет относится к возвращаемому наблюдению, не к тексту всей вкладки, истории чата или числу токенов. Он не загружает следующие строки, письма, страницы или тело ещё не открытого объекта. `read_page` отдельно имеет max_chars/max_elements и offsets; для свёрнутых коллекций используй [группы и порции](#отложенные-группы-и-чтение-порциями). Даже full может быть усечён исходным чтением.

Сохраняются типы, ID, состояния, видимость и перекрытие оставленных элементов, включая ссылки и select. `truncated` и `summary_omitted` показывают потери. Заголовок, выбранное состояние или важная строка могут оказаться за пределом первых N элементов; цель последнего действия не гарантированно находится в начале. Увеличивай контекст для сравнения объектов, анализа содержимого, неоднозначного выбора и проверки значимого результата. Не повторяй изменяющее действие ради получения более длинного ответа: после него используй новое read_page или ограниченное ожидание.

Отсутствие в compact не доказывает отсутствие на странице. Для «найти все», сравнения условий и проверки перед отправкой/удалением сначала получи достаточное покрытие. Source next_* offsets относятся к исходному чтению: не используй их, чтобы перепрыгнуть элементы, опущенные только итоговым compact. При новом чтении используй новые ID. Сокращай бюджет лишь когда подтверждено, что оставшихся данных достаточно.

## Отложенные группы и чтение порциями

Обычный `read_page` по умолчанию сворачивает поддержанные семантические коллекции в `groups` независимо от размера: списки, меню, группы строк и варианты native select. Заголовки вне свёрнутых групп сохраняются в пределах общего бюджета. Произвольные повторяющиеся div автоматически не классифицируются; заголовки и элементы управления внутри свёрнутой группы требуют её чтения. Сворачивание относится к данным Brodex и не меняет интерфейс сайта.

`group_id` обозначает группу только в текущем снимке. `kind` различает rows/options/items; `content:deferred` означает, что содержимое ещё не прочитано. `count_lower_bound` — нижняя граница, `total:null` — точное число не установлено. Не выводи число всех записей из числа DOM-узлов: виртуализированные и серверные списки могут содержать больше данных. `visible:false` не разрешает действия со скрытыми пунктами.

Если задача требует содержимое группы, вызови `read_page` с `group:{snapshot_id,group_id}` из последнего наблюдения и тем же выбранным frame_id. По умолчанию порция содержит до 50 непосредственных элементов (options для select); необязательный limit — 1–100. Действуют также max_chars/max_elements, ограничение обхода 30000 узлов и проверяемый между шагами бюджет времени 250 мс. Это не жёсткий предел длительности отдельного вызова браузера или расчёта layout. `read_budget` показывает обход основного чтения, а не суммарную работу всех внутренних проверок.

Для следующей порции используй **новый** snapshot_id, `group_page.group_id` и `group_page.next_cursor` как cursor. Не вычисляй курсор и не используй offsets одновременно с group. Каждая порция заменяет предыдущий снимок для действий. `has_more` показывает наличие продолжения в выбранном DOM-поддереве; вложенные groups остаются отдельными запросами. Порция может закончиться внутри строки из-за бюджета текста или элементов: `items_started` не означает число полностью прочитанных строк. Длинный текст продолжается с сохранённой позиции. Варианты native select выдаются в options; это данные выбора, а не разрешение нажимать скрытый option. Если обзор достиг предела 50 описаний групп, он также возвращает `group_page` с курсором продолжения обзора; используй тот же порядок запроса, чтобы получить оставшиеся группы и содержимое после них.

При GROUP_CHANGED, GROUP_SNAPSHOT_STALE, GROUP_NOT_FOUND или GROUP_CURSOR_INVALID получи новый обзор и заново выбери группу. Изменения внутри группы и её предков, смена документа или истечение снимка прекращают продолжение; несвязанные текстовые изменения не требуют перечитывания группы. Курсор не предоставляет замороженную копию страницы: состояния полей проверяются заново перед действием. Не обходи отказ автоматическим сбросом курсора и не продолжай сравнение как будто список неизменен. Если порция не продвигается из-за лимита, не повторяй её бесконечно; выбери более узкую доступную группу, фильтр сайта или визуальное наблюдение.

Сокращение наблюдения не отключает проверку действия. Элемент из порции проходит общий prepare_action → контроль → execute_prepared_action; внутренняя подготовка сохраняет именно выбранный DOM-объект, даже если он отсутствует в обзоре. Для восстановления после отказа сначала найди нужный объект в свежем наблюдении. Не переноси element_id между порциями.

Коллекции, не отображаемые из-за `display:none` у них или предка, могут храниться внутри контекста поля без подробной геометрии каждого пункта. Изменение текста или состава внутри такого поддерева само по себе не останавливает соседнее действие. Раскрытие, замена, потеря привязки, изменение проверяемого состояния контролов или влияние на геометрию и доступность цели остаются основаниями отказа. `visibility:hidden` не является достаточным условием: потомок может быть видимым. `context_coverage.deferred_hidden_collections` сообщает число компактно учтённых скрытых коллекций. При координатной подготовке и повторной проверке неотображаемые поддеревья пропускаются, но новые видимые элементы и перекрытие цели проверяются заново.

Для обычного native `<select>` применяется гибридный контроль. Неотображаемый элемент либо закрытое однострочное поле учитываются компактно, без подробного обхода `<option>`/`<optgroup>` в контексте формы. Сам элемент, его геометрия, доступность и выбранные варианты остаются проверяемыми; `context_coverage.compact_selects` показывает число таких полей. Изменение невыбранных вариантов само по себе не останавливает соседнее действие. Смена выбранного варианта, его подписи, значения, доступности или идентичности, замена списка либо переход к раскрытому/многострочному виду останавливают устаревшее действие. При действии по самому select сохраняются проверки идентичности цели и доступности выбираемого варианта. Это не исключение ошибок. Видимые `multiple`, списки с `size>1` и раскрытые списки остаются с подробной проверкой. Если браузер не поддерживает определение `:open`, видимый список не получает компактный контроль. Настраиваемые select с вложенными button/selectedcontent не сокращаются этим адаптером. Для скрытого multiple выбранные варианты проверяются полностью в пределах 256; превышение даёт явный отказ.

Чтение вариантов порциями и визуальное раскрытие независимы: для получения `options`, в том числе малого списка, не требуется открывать меню. Используй запрос группы, затем обычную подготовку выбора по прочитанному value. `act select` по-прежнему поддерживает только одиночный выбор и проверяет доступность варианта; компактный контроль не добавляет поддержку множественного выбора. Сворачивание данных не делает видимый значимый контекст некритичным. Видимый большой контекст, неподдержанная поверхность или неполная проверка состояний по-прежнему могут дать DOM_CONTEXT_LIMIT; лимит ответа и limit группы эту проверку не расширяют. Изменение содержимого группы может разрешать соседнее действие, но всё равно аннулирует курсор чтения этой группы.

## Поля и редакторы

`editable`, `readonly`, `disabled`, `focused` помогают выбрать поле, но не заменяют проверки перед действием. haspopup/expanded — признаки, не гарантия раскрытия по наведению. Если поле не редактируется, проверь, не открывает ли оно отдельный редактор. При недостатке метаданных используй read_page_code или снимок; не собирай CSS всех полей заранее.

Для contenteditable поддержанного документа: сфокусировать проверенным кликом → новое read_page → fill. Инструмент проверяет editing host, фокус, видимость, перекрытие, readonly и выделение; Input.insertText вызывается один раз. Ввод заменяет всё содержимое, не отправляет его. Не заменяй существующий черновик без разрешения. Отправка — отдельное действие после проверки.

`EDITOR_FOCUS_REQUIRED` требует фокуса и нового чтения; `EDITOR_SELECTION_CHANGED` — нового наблюдения; сложные вложенные редакторы могут дать `EDITOR_COMPLEX_CONTENT_UNSUPPORTED`. После unknown ввод не повторять автоматически. Пароли и секреты регулируются постоянными ограничениями основного файла.

Для стилизованных checkbox/radio используй наблюдаемую interaction_surface: native_label или native_toggle_surface. Не нажимай скрытый input напрямую. Общий label иногда открывает строку вместо переключения: проверь эффект. Мгновенное старое checked или disabled во время применения не означает неуспеха; дождись наблюдаемого конечного состояния. Неизвестное/indeterminate не выдавай за false.

## Клавиши

`press_key` работает в проверенном текущем фокусе выбранного документа, включая поддержанные iframe и открытый Shadow DOM; не выбирает поле сам. Нужен свежий snapshot_id и основание, куда попадёт клавиша. Поддержаны Enter, Tab, Escape, Backspace, Delete, стрелки, Home/End, PageUp/PageDown, Space, Ctrl+A/C/V/X/Y/Z; Shift/Ctrl только в поддержанных сочетаниях. Alt-клавиши и горячие клавиши браузера/ОС не поддерживаются, даже если enum modifiers общий с мышью.

Копирование, вставка, удаление и отправка формы требуют соответствующей задачи. Не вставляй неизвестное содержимое буфера. Отправка Enter не подтверждает результат; проверить страницу. Модификаторы отпускаются внутри команды, постоянного удержания между вызовами нет.

## Проверка асинхронного результата

Предпочитай `wait_after` после отправленного действия, когда известен наблюдаемый критерий. `wait_for` только читает: default 5000 мс, максимум 10000 мс на очередь/readiness/чтения; нулевой бюджет не выполняет чтение. all/any до четырёх условий, stable_ms требует повторных совпадений. any должна сохранять одну и ту же совпавшую альтернативу.

element_state требует точного kind/name единственного видимого неперекрытого элемента и полного покрытия; проверяет checked/selected/disabled/expanded. Это текущее состояние, не доказательство перехода. Отсутствие текста достоверно лишь при полном текстовом покрытии. WAIT_TIMEOUT/matched:false означает «не подтверждено», а не «действие не произошло».

Если элемент не появился, проверь усечение и возможную загрузку, затем одно ограниченное ожидание и новое решение. Не запускай бесконечный опрос или повтор клика. Для изображения, геометрии или визуального результата нужен новый screenshot. После смены URL сверь вкладку и новую страницу; не продолжай по старым ID. Не обязательно ждать всей сетевой активности, не влияющей на цель.

## Управление таймингами операций

Агент может подбирать поддержанные тайминги под наблюдаемое поведение интерфейса без отдельного согласования каждого значения. Проверяй актуальную схему: настраиваемое ожидание результата не означает, что доступны любые внутренние задержки Brodex.

| Параметр | Как применять |
|---|---|
| `wait_after.timeout_ms` у поддерживающего его действия, `wait_for.timeout_ms` | Бюджет проверки результата, 0–10000 мс, по умолчанию 5000. Результат может подтвердиться раньше; это не обязательная пауза. Нулевой бюджет не читает страницу. |
| `wait_after.stable_ms`, `wait_for.stable_ms` | Сколько должно сохраняться одно и то же совпавшее условие: 0–3000 мс. Выбирай меньше timeout_ms с запасом на очередь и чтения. Стабильность текста/состояния не доказывает окончания движения элемента. |
| `drag.duration_ms` | Длительность движения указателя: 200–3000 мс, по умолчанию 700. Подбирай по реакции перетаскиваемого объекта; это не ожидание загрузки или проверки результата. |
| `timing` | Необязательный объект у wait_stable, prepare_click/prepare_operation, mouse_click, execute_operation и act hover/hover_at/click_at/wheel_at. Defaults: timeout_ms 3000, stable_ms 200, poll_interval_ms 100, delay_ms 0. Timeout 50–10000, stable/delay 0–3000, poll 50–500 мс; delay+stable ≤ timeout. |
| `execute_operation.result_timing` | Та же структура для проверки результата каждого шага; default timeout_ms 5000, остальные значения как у timing. |
| `execute_operation.total_timeout_ms` | Общий бюджет серии: default 25000, допустимо 1000–25000 мс. Не продлевает исходные 30 секунд контрольного снимка. |

- **Меню появляется с задержкой после наведения:** одно `act hover` с `wait_after` на наблюдаемый пункт/состояние, либо затем `wait_for`. Выбирай timeout по наблюдаемой задержке с запасом. Например, 3000 мс и stable_ms 200 — начальная оценка для короткой подгрузки, не правило всех сайтов. Для `element_present` нужен `text`; kind/name относятся к `element_state`. Не повторяй hover/клик только из-за таймаута.
- **Кнопка или меню продолжает анимацию:** по свежему DOM выбери element_id и вызови `wait_stable`, обычно без timing. Он ждёт устойчивости цели и влияния её предков, включая активные анимации; ничего не нажимает и не выбирает другую цель. После успеха или таймаута старый снимок аннулируется: новое чтение/обзор, затем подготовка действия. Текстовый stable_ms у wait_for не заменяет эту проверку.
- **Результат грузится дольше обычного:** увеличь бюджет только соответствующей проверки в пределах схемы, а не все задержки задачи. После timeout сначала установи текущий этап. Новое ограниченное ожидание оправдано новым признаком продолжающейся загрузки; повторное изменяющее действие — нет.
- **Интерфейс стабильно отвечает быстро:** сокращай избыточное окно стабильности и бюджет на основании нескольких наблюдений. Сохраняй проверку результата. Не переноси удачный тайминг одного сайта на другой и не пытайся исправить неверную цель увеличением паузы.

Ожидание выполняй до подготовки координатного ввода либо после отправленного действия. Между `prepare_click` и кликом не вставляй `wait_for`/новое чтение: они заменяют снимок. Если контекст изменился или подготовка просрочена, новое ожидание не оживляет старое разрешение — нужна новая подготовка и просмотр контроля. После наведения страница могла измениться даже при отказе клика.

`timing` применяется к конкретной фазе: prepare — проверка фиксированного контекста до кадра; mouse_click/click_at/wheel_at — после реального наведения до ввода; act hover_at — устойчивость подготовленной области до движения; act hover — устойчивость самого элемента наведения, а не доказательство появления меню. Для содержимого меню используй wait_after/wait_for; затем при необходимости wait_stable по его пункту. delay_ms задаёт минимальное время до окна стабильности. execute_operation без timing наследует настройки подготовки; result_timing использует собственный default 5000 мс, в том числе при изменении только stable_ms. Возвращаемые effective/elapsed_ms/probes показывают применённые значения и измеренный исход.

Увеличение timing не разрешает переждать подмену, смещение, перекрытие или изменение смысла просмотренной цели. Эти нарушения прерывают подготовленный ввод сразу. После ожидаемого сдвига нужна новая подготовка; для серии — новый просмотренный план после установления частичного результата. Фиксированные длительности подсветки и стабилизации viewport остаются внутренними, не передавай вымышленные аргументы. Применяй новые поля только если они присутствуют в подключённой MCP-схеме. В заметке о проблеме достаточно фазы, бюджета, фактического времени/исхода и причины изменения, без содержимого страницы.

## HTML/CSS для диагностики

`read_page_code scope:page` — очищенный текущий DOM, не оригинальный ответ сервера, не JavaScript и не архив сайта. scope:element — HTML элемента, computed CSS, ограниченные подходящие css_rules и родители. Выбирай свежий element_id либо наблюдаемую точку снимка; не угадывай селекторы и не исполняй код страницы.

Для отказов видимости проверь display, visibility, opacity, hidden, inert, pointer-events, размеры, перекрытие и предков. css_rules — кандидаты; фактический стиль определяется computed. Прозрачный элемент можно диагностировать, но чтение не разрешает взаимодействие с невидимой целью.

Учитывай max_chars/offset, scan_limit, css_truncated, inaccessible_stylesheets. Значения форм, script/style, contenteditable, iframe/template и URL-параметры фильтруются, но обычный текст/id/class может быть чувствительным. Не считывай cookies/хранилища для диагностики. Не сохраняй DOM автоматически; по явной просьбе сохранить очищенный код используй .txt/.html.txt и обозначь ограничения. Отображай нужный код в блоках html/css, без секретов.

## Самостоятельное DOM-наведение

`act hover` физически перемещает указатель к DOM-элементу без нажатия. Применяй для подсказок, карточек свойств, меню и появления дополнительных кнопок. Нужен свежий element_id с guarded-контекстом и доступной поверхностью наведения. Изображение с pointer-events:none не равно принимающему события контейнеру. При DOM_CONTEXT_REQUIRED или отсутствии подходящего ID оцени видимую область на снимке и используй [координатный hover](visual-actions.md#самостоятельное-координатное-наведение), если нет перекрытия или запрета безопасности. Не имитируй hover попыткой клика. После отправленного наведения проверь содержимое; при задержке — wait_after/wait_for, а не повторное наведение.


## Каталог DOM-объектов

Если нужны карточки объектов, связи или поиск по DOM, используй необязательный режим `read_page.catalog`, когда он присутствует в схеме подключённого MCP. Режимы: overview, search, details, children. Обзор сворачивает коллекции; children читает непосредственных детей, включая generic. Для уточнения передавай ref и observation_id из последнего ответа каталога; для продолжения — cursor с новым observation_id и прежними mode/text/exact.

Различай coverage.scan_complete (завершённость обхода в выбранном режиме) и text_complete (отсутствие усечения текста). Общий complete остаётся строгим: полный обход при усечённом тексте не доказывает отсутствия совпадения в поиске. Свёрнутые группы требуют отдельного чтения. Курсор означает оставшуюся работу, но не гарантирует непустую порцию при фильтрации или ограничении бюджета. Связи могут ссылаться на узлы, карточки которых ещё не запрошены. Имя в name — DOM-эвристика. coverage.sections отдельно показывает статус идентификации, имени, текста, состояний, связей, видимости, перекрытия, детей, операций и AX. read относится к указанному scope, а не ко всем возможным свойствам объекта.

Каталог возвращает observation_id/ref вместо snapshot_id/element_id. Не передавай ref вместо element_id в act. Для точной цели из каталога используй prepare_action(command:act, catalog_target:{observation_id,ref}, parameters) без snapshot_id/element_id и координат. Поддержаны click/fill/select/set_checked/hover/scroll. Инструмент разрешает исходный узел и запускает обычную подготовку; generic не становится button и не ищется заново по имени или ID. Просмотри новый контроль и только затем выполни execute_prepared_action. Прежние проверки контекста, состояния, перекрытия и одноразовости сохраняются. Чтение каталога не заменяет и не продлевает снимки прежнего исполнителя; новое чтение каталога заменяет его собственное наблюдение. Ссылки истекают через 60 секунд и отклоняются при наблюдаемой DOM-мутации или смене рабочей сессии.

На этом этапе каталог читает основной документ и открытый Shadow DOM; содержимое iframe и slot не поддержано и отражается в coverage. Для iframe используй обычное чтение. Не сочетай catalog с group, прежними лимитами/offset или frame_id, отличным от 0. Каталог не обязателен перед обычным действием.


При details каталог проверяет CSS/layout и ограниченный набор точек elementFromPoint без движения указателя. occluded:false означает доступную проверенную точку, true — перекрытие всех проверенных точек, null — недостаточно данных. occlusion.scope и status указывают границы проверки; это не оценка каждого пикселя. capabilities.candidates содержит blockers и assessment: blocked/not_checked/requires_preparation. Ни один из этих статусов не разрешает действие; окончательная проверка выполняется подготовкой и исполнителем.

Для браузерной роли и имени можно передать catalog.ax:true. AX сопоставляется по точному backend DOM node в наблюдаемом изолированном мире расширения, максимум для 20 возвращённых карточек. Проверяй ax.status, ax_coverage и consistency; observation_changed требует нового чтения. unavailable не разрешает подменять контекст или сопоставлять узлы по похожему тексту. Значения форм, описание и сырые AX-источники не выдаются. AX-only узлы отдельно не перечисляются. Без ax:true запросов AX нет.
