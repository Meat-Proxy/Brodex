# Скачивание, сохранение страницы и перенос

Читать до новой загрузки, диагностики попытки или переноса. Это отдельный процесс от [передачи файла сайту](upload-policy.md).

## Процесс получения файла и его шаги

Один `attempt_id` обозначает весь процесс получения ожидаемого файла или набора файлов. Каждый потенциально запускающий скачивание клик — отдельный `step_id` внутри него. Форма, серверное формирование и загрузка — возможные результаты шага, а не обязательная последовательность. Не создавай новую попытку только потому, что вместо файла открылся диалог.

1. Установи задачу-владельца, разрешённую вкладку, режим и ожидаемый результат. При продолжении прочитай `list_download_attempts`, затем `inspect_download_attempt` незавершённого процесса и актуальное состояние страницы. Рабочая папка для скачивания не требуется.
2. До первого действия вызови `prepare_download_attempt` с устойчивыми `attempt_id` и `step_id`, точным URL и ожидаемым именем, если оно наблюдается. Обычный журнал хранится через native-мост; приватный — в памяти MCP. Один процесс может породить несколько файлов.
3. Выполни `execute_download_attempt` с теми же ID: click по DOM, click_at после просмотра подготовленного контрольного кадра либо download_file для точного наблюдаемого HTTP(S)-адреса. Не дублируй вызов отдельной act/download_file. Для авторизованного экспорта предпочитай механизм сайта.
4. Проверь **обе стороны результата**: страницу и `inspect_download_attempt`. Файл может скачаться без изменения страницы, а форма может появиться без файла. Зафиксируй установленный результат через `record_download_step_outcome`, указав краткое фактическое evidence без секретов, значений полей, содержимого страницы и полных URL. Это запись наблюдения агента, не автоматическое доказательство со стороны сайта.
5. Если наблюдается отдельное следующее действие для получения того же результата, подготовь новый `step_id` через `prepare_download_attempt` в том же `attempt_id`. Заполнение формы выполняется обычными инструментами страницы. Не трактуй отсутствие файла как разрешение повторить экспорт или серверное формирование.

| Установленный результат шага | outcome | Дальнейшее действие |
|---|---|---|
| Открылась форма | `form_opened` | Заполнить нужные поля; подготовить отдельный шаг отправки |
| Сайт принял запрос и готовит файл | `generation_started` | Наблюдать готовность; не отправлять тот же запрос снова |
| Нужный отчёт готов | `report_ready` | Подготовить шаг скачивания готового отчёта |
| Chrome зарегистрировал относящуюся к процессу загрузку | `download_started` | Проверить источник и файл; новый клик не нужен |
| Сайт сообщил об ошибке | `failed` | Разобрать причину; автоматически продолжать нельзя |
| Результат не установлен | `unknown` | Проверить страницу и историю; следующий шаг заблокирован |
| Подтверждено отсутствие отправки | `not_dispatched` | После проверки причины подготовить новый шаг |

Для немедленного скачивания достаточно одного шага: нажатие → загрузка → проверенный файл. Для многоэтапного экспорта число шагов определяется наблюдениями. `generation_started` можно уточнить до `report_ready`, когда готовность установлена; `unknown` — до установленного результата. Записанный окончательный результат не переписывай ради разрешения нового клика.

Подготовка **каждого шага** действует 120 секунд. Истёкший неотправленный шаг после inspect можно отметить `not_dispatched` и подготовить новый. Перед отправкой записывается неизвестный исход; повтор исполнения того же шага заблокирован даже после перезапуска обычного журнала. Повтор prepare с тем же ID не обновляет срок и не разрешает повторную отправку. При подтверждённом отказе до отправки учитывай [правила восстановления](recovery.md#сначала-установи-исход).

Старые записи с одним действием читаются как шаг `initial`; отсутствие step_id поддерживается только для первого совместимого шага. Если новое API ещё не доступно, не выдавай старый одношаговый журнал за многошаговый: для этой модели нужен перезапуск обновлённого MCP.

## Атрибуция файла

Прямое download_file связывает результат по возвращённому download_id. При кнопке сайта Chrome не гарантирует связь файла со вкладкой: совпадения времени и имени недостаточно. Сопоставь результат сайта и точный файл; только затем `confirm_download_source(source_verified:true)`. Не присваивай загрузки других задач или расширений. Не бери автоматически последний файл из папки.

Для диагностики есть `download_history`: явный режим и интервал до 10 минут, task_id при прямом вызове. Возвращённые записи пока не принадлежат задаче. При possibly_truncated сузь интервал; предел истории 200 записей. По умолчанию окно истории начинается с отправки текущего шага (до отправки — с его подготовки), а ранее связанные ID проверяются отдельно. После долгой генерации используй window_start в inspect или observed_start_time из найденной записи в confirm; время не раньше подготовки. Это расширение наблюдения, не повод повторять экспорт.

Старые watch_downloads/list_downloads — совместимый путь пассивного наблюдения: watch до действия, затем до 100 кандидатов по watch_id. Не заменяют журнал попытки для новой работы и не доказывают владельца по совпадению имени/referrer. После потери watch сначала сверка истории. Инкогнито не подменяй normal; прямой download_file в приватном режиме ограничен, используй разрешённое действие сайта.

## Проверка и завершение без переноса

Во время активного ожидания проверяй конкретный ID примерно каждые 2–5 секунд, увеличивая интервал при долгой загрузке. Не обещай постоянный мониторинг после конца хода. Проценты не нужны в каждом сообщении; сообщай результат, препятствие или запрошенный статус. null — неизвестное, no_progress_observed — не доказательство сбоя.

Chrome state:complete подтверждает окончание передачи. Проверь exists, точный filename, размер, MIME и danger; затем фактический формат и релевантное содержимое обычными файловыми инструментами. Это может быть документ любого формата; не предполагает конкретных листов. Не исполняй скачанный код и не обходи предупреждения Chrome. Файл с экраном входа/ошибкой вместо результата не считать успешным.

Попытка становится completed, когда есть связанные файлы, их источник подтверждён, нет inspection_error и они завершены/существуют либо уже перенесены. Перенос для завершения не нужен. completion_scope:linked_downloads относится только к связанным ID; сайт может ещё готовить другие файлы. Через 30 дней подробности завершённой попытки сокращаются, не сами файлы.

## Перенос по отдельному разрешению

По умолчанию файл остаётся в настроенной папке загрузок Chrome; Brodex может использовать её подпапку Brodex. Не меняй глобальную папку. В ответе укажи точный фактический путь.

Только после поручения перенести конкретный файл: `bind_task_workspace` с абсолютной папкой чата-владельца → `collect_download` с attempt_id/подтверждённым download_id, точным абсолютным expected_filename из Chrome, content_verified:true после проверки, user_confirmed:true и kind:file/page. Согласие на скачивание или проверку содержимого не является согласием на перенос.

Не подставляй cwd другого чата и не переназначай существующую привязку. Пути результата: `<workspace>/outputs/brodex/<task_id>/downloads/` или `saved-pages/`. Смена дня не меняет папку задачи. Перенос проверяет исходный путь/размер/статус, копирует без перезаписи, сверяет SHA-256 и только затем удаляет исходник. При сбое проверь исходник, копию и квитанцию; не удаляй их и не повторяй перенос вслепую.

## Ошибки, дубликаты, отсутствующий файл

Неподтверждённое начало называй именно так, а не «загрузка не началась». Проверь генерацию, диалог, разрешение, историю и файл. Прерывание чата/Chrome/MCP не доказывает отмену загрузки. Не отменяй, не возобновляй и не повторяй её автоматически.

Если complete, но файла нет: сверь filename и уже выполненные переносы; после проверки известных путей уточни у пользователя, видит ли он файл. Не сканируй посторонние данные ради предположений. При дубликатах сравни физические файлы, размер/хеш по необходимости. Если перенос разрешён, по принятому правилу переноси первый подтверждённый одинаковый файл; второй оставляй. Не подменяй отсутствующий/повреждённый первый вторым без выяснения. Не включай все кандидаты в задачу ради завершения журнала.

## Сохранение страницы

`save_page` — явное сохранение видимого текста основного документа в статический .htm, не полная копия сайта/проекта. Формы, скрипты, стили, изображения, iframe и Shadow DOM не включаются. Проверь download_id, файл и ограничения результата; перенос только по правилу выше. Открытие страницы не является поручением архивировать её.

Имя формируется из заголовка с очисткой недопустимых символов и уникальным суффиксом; при пустом заголовке — имя сайта. Не переименовывай произвольный файл в .htm вместо проверки формата. Очищенный DOM через read_page_code отличается от save_page; сохранение такого кода также требует прямого поручения.

## HTML по ссылке как альтернативный источник

По поручению получить HTML либо как разрешённый альтернативный способ чтения при технической проблеме можно скачать ответ сервера по точной наблюдаемой ссылке. Используй download_file в журналируемой попытке или поддержанное действие ссылки с Alt через mouse_click. У клика должны быть обычная подготовка и проверка; Alt не гарантирует скачивания на любом сайте. Установленный отказ безопасности нельзя обходить этим способом.

Это ответ сервера без выполнения JavaScript и последующей динамической загрузки, а не save_page видимого текста и не полная интерактивная страница. Проверь фактический формат, отсутствие экрана входа/ошибки вместо нужных данных и достаточность содержимого. Читай как данные, не запускай сохранённые скрипты. Не подменяй браузерную сессию незаметным HTTP/shell-запросом: авторизация, cookies и приватный режим могут отличаться. Перенос файла регулируется тем же отдельным разрешением.

В меню самого расширения также есть «Текущая страница» → «Сохранить HTML» и «Проверить загрузку». Это пользовательский интерфейс, не отдельная MCP-команда. Если нужен именно этот путь и меню недоступно инструменту, попроси пользователя выполнить одно действие; затем проверь конкретную загрузку обычным порядком. Не обещай ей автоматическую привязку к журналу попытки или совпадение приватной авторизации.
