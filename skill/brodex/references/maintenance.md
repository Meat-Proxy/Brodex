# Сопровождение навыка Brodex

Читать при изменении навыка или проверке совместимости с новой версией. Этот файл задаёт структуру документации, не последовательность обычной браузерной задачи.

## Разделение ответственности

- SKILL.md: назначение, маршрутизация, общий цикл, разрешения и границы остановки. Должен позволять начать работу без чтения всех справочников.
- commands.md: полный перечень доступных MCP-команд, назначение, существенное условие и способ проверки результата. Точные схемы не копировать целиком: агент получает их из инструмента.
- tasks-tabs.md: жизненный цикл задач и принадлежности; workflow.md: только записи журнала; page-actions.md и visual-actions.md: методы и наблюдение.
- download-policy.md и upload-policy.md: отдельные направления движения файлов и их полномочия.
- recovery.md: ошибки, неопределённость, остановка и транспорт; storage.md: данные и сроки.
- История версий, конкретные сайты, тестовые отчёты, пути исходников конкретной установки и бэкапы — в документации проекта вне пакета навыка. Не возвращать журнал изменений в начало SKILL.md.

## Формат правила

Пиши по ситуации: **условие → решение/команда → проверяемый результат → действие при отказе**. Обязательную последовательность задавай там, где нарушение действительно меняет корректность, например подготовка координатного ввода или переходы журнала. Для выбора меню/поиска/DOM/мыши оставляй решение по наблюдениям.

У правила одно основное место. В другом файле — краткий инвариант и ссылка, не несколько слегка разных подробных копий. Используй устойчивые тематические заголовки, таблицы решений и короткие предметные примеры без конкретных сайтов. Не добавляй новые справочники, если тему можно однозначно поместить в существующий.

Явно различай: правило пользователя, поведение кода, ограничение инструмента, рекомендацию агента и непроверенную возможность. Не превращай единичный инцидент в универсальный запрет. Не выдавай тест одного случая за гарантию всего класса. Не описывай будущую возможность как существующую.

## Порядок изменения

1. Зафиксируй исходные файлы вне установленного пакета. Прочитай только затронутые разделы и входящие ссылки.
2. Сверь актуальные имена/схемы MCP и реализацию спорного поведения. Схема доказывает доступные аргументы, но не пользовательское разрешение. При расхождении останови зависимое действие и опиши факт, не выбирай более широкую трактовку.
3. Сформулируй, какое поведение агента должно измениться и какой результат подтвердит улучшение. Для чистой редакционной правки поведение должно сохраниться.
4. Обнови основное место правила, каталог команды и маршрут чтения, если затронуты. При изменении API проверь также описание MCP. Удаляй заменённое правило вместо добавления «начиная с версии X прежнее не действует».
5. Проверь полноту команд, относительные ссылки, YAML, ограничения полномочий и противоречия. Ни одна команда не должна исчезнуть из каталога случайно. Совместимые/отключённые команды явно помечай.
6. Проверь типовые решения по сценариям ниже. Для runtime-изменений нужны соответствующие живые/изолированные тесты. Для документации структурная проверка не доказывает улучшения поведения модели.
7. Установи проверенные файлы. Перезапуск MCP нужен при изменении его загруженных схем/описаний; изменение только Markdown не требует обновления расширения. Сохрани итог и ограничения вне навыка.

При разработке расширения найди актуальную установленную копию и её исходники по документации проекта; не принимай путь прошлой установки за универсальный. Собственную версию сверяй по version_name и VERSION.txt. Техническую версию исходной базы не повышай только ради подавления предупреждения совместимости. Резервные копии и результаты тестов держи вне установленного пакета навыка.

## Регрессионные сценарии решений

| Входная ситуация | Ожидаемое решение |
|---|---|
| «Открой сайт», уже есть личная вкладка с тем же URL | Новая группа задачи; не присвоить личную вкладку |
| Пользователь прямо указал личную вкладку | attach в пределах поручения, без постоянного восстановления |
| Группа недоступна, привязка есть | Попросить открыть сохранённую; копия только по прямому поручению |
| Вкладка вынесена из группы | Прекратить действия/повторы в ней |
| DOM-клик отправлен, визуального эффекта нет | Проверить результат/загрузку, затем выбрать метод; не повторять вслепую |
| Контекст изменился после подготовки | Новое наблюдение и переоценка, без клика по старому ID |
| Полный отказ координатного действия, все изменения допустимы | Анализ критичности в чате → новый обзор → выбор повтора и второй комментарий → prepare_retry → просмотр контроля → execute_retry → проверка эффекта |
| Отказ содержит критичное или неясное изменение | Краткий анализ в чате → новое наблюдение → обычное планирование; специального повтора нет |
| После обзора выбрано обычное действие | Не требуется отдельный комментарий о выборе повтора |
| DOM-действие остановлено изменением контекста | Анализ → свежее DOM-чтение, снимок по необходимости; использовать DOM-контроль и control_token для точного повтора, не подменять элемент |
| DOM меняется во время захвата обзора | PNG с индексом изменений и полнотой учёта; изменения DOM сами по себе не отменяют обзор |
| При захвате сменился документ, viewport или прокрутка | Отмена обзора допустима; заново установить страницу/координатную основу |
| Большая страница, короткая видимая цель | Обзор без глобального подробного эталона → свежий контроль цели; размер несвязанного DOM не запрещает ввод |
| Переполнение журнала изменений | Указать причину и неполноту; отдельно проверить полноту выбранной цели |
| Удаление/вставка среди повторных текстовых обновлений | Объединить обновления по узлу, сохранить структурные события и выделить их в порядке выдачи |
| Диагностика захвата неполна или DOM-мутаций нет | Не объявлять все элементы или пиксели неизменными |
| Повтор остановлен новым изменением | Полный текущий отчёт; весь набор исключений заново, без переноса старого набора |
| Повтор отправлен, ответ потерян | Проверить результат; одноразовый retry_id не исполнять заново |
| Редактор содержит черновик | Не заменить fill без разрешения; проверить фокус/эффект отдельно от отправки |
| Кнопка сразу запускает скачивание без изменения страницы | Один attempt_id и один step_id; проверить загрузку и файл |
| Кнопка открывает форму, затем сервер готовит отчёт | Один attempt_id, отдельные шаги с установленным результатом; не повторять формирование |
| Исход шага неизвестен после обрыва | Сверить страницу и загрузки; не создавать новый шаг для обхода блокировки |
| Скачивание завершено, переноса не просили | Проверить файл, дать фактический путь, завершить попытку без collect |
| Одновременно скачаны два похожих файла | Проверить связь по ID/результату сайта; не брать автоматически последний |
| Требуется файл на сайте | Разрешение на конкретный файл/сайт до выбора; assigned не успех |
| Цепочка журнала частично записана | Сверить ревизию и продолжить неприменённое; не повторять действие сайта |
| Команда занята, пользователь просит остановить | Out-of-band stop, проверить cleanup; не продолжать автоматически |
| OTP/CAPTCHA/секрет | Передать действие пользователю и end; не переписывать секрет |
| Ответ агентом закончен, пользователь не завершал задачу | end, группа остаётся |
| Пользователь подтвердил завершение задачи | Удаление рабочей группы по согласованному правилу и точному составу |

Оцени отдельно: охват возможностей, соблюдение границ, корректность результата, лишние обращения и объём читаемой документации. Уменьшение размера файла само по себе не доказывает ускорения или улучшения качества. Проверку в новом контексте модели отмечай отдельно от авторской проверки; не заявляй независимый тест, если его не было.

## Расширение общего процесса подготовки

Новый вид действия подключай адаптером к общей подготовке, одноразовому исполнению и восстановлению, не вводя отдельный цикл исключений. Проверяй отсутствие ввода при подготовке, сохранение цели и параметров, отсутствие быстрого повтора в action_v2, новые полные отчёты отказов, одноразовые правила только на связанное исполнение, новые препятствия, истечение контроля, неизвестный и частичный исход. Поддержка семейства действий не означает поддержку любого iframe, Shadow DOM или скрытого элемента. Старые способы вызова сохраняй, пока миграция не проверена.
